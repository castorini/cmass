System details

JevGPT with document BM25

JevGPT combines GPT-6.1 Sol high as System Two with Jev-1.13.0 as System One for parallel source inspection and evidence selection. The harness is based on Pi-Serini. This entry uses whole-document BM25 (k1 = 0.9, b = 0.4) and a 1,800-second research budget. Jev is an evidence model, rather than a separate ranking stage applied to the displayed BM25 hits.

All 423 answers were independently graded with the same GPT-6.1 Sol high prompts used for the Piika results, with tools disabled. Strict accuracy is 396/423 (93.62%); relaxed accuracy is 398/423 (94.09%). The independent judge accepted one additional DSQA answer relative to the sender’s grades; the original and independent aggregate counts are retained in the provenance.

P@all, R@all and H.G. count unique parent documents displayed as ranked hits in search and read_search_results. Internal candidate pools, System One inspections and auto-scan evidence notices are separate views. Notices can occur within a search response; including them changes some retrieval scores. The aggregate results include that sensitivity analysis. Unjudged documents count as non-relevant, and no qrels were expanded from these runs.

Selected outputs and their hashes were verified. The full history of unselected attempts is unavailable, so selection independent of correctness could not be established. Paper · Harness code · Pinned runs

Metrics

What each column measures

Acc.
Percentage of all questions answered correctly; unanswered questions count as failures. DSQA ranks strict exact-set equality: every gold member and no incorrect additions, in any order. The secondary relaxed score accepts a nonempty subset with no incorrect additions.
P@all
Precision@all: the percentage of the distinct documents in a question's search results that are qrels, averaged over questions. Unjudged documents count as non-relevant, so it is a lower bound.
R@all
Recall@all: the percentage of a question's qrel documents that appear in any of its search results, each counted once, averaged over questions.
H.G.
Hop groundedness: the percentage of a question's hops supported by at least one retrieved document, averaged over questions. It uses hop-level judgments that are not released.
T.C.
Mean Piika tool calls per question: searches plus document reads. JevGPT has additional tools, so its counts appear in the separate tool breakdown.
Closed-book
Accuracy from the question alone, with all tools disabled at the API level. JevGPT has no matched closed-book evaluation; its entries are unavailable.

Setup

How the runs were made

Agent harness
The baseline rows use Piika, a search-agent framework following the Pi-Serini design. The new document-BM25 entry uses JevGPT, also based on Pi-Serini, with Jev-1.13.0 for evidence inspection.
Tools
Piika exposes search (at most five previews) and read_document (first 200 lines by default). JevGPT adds read_search_results and jev_find. Its internal evidence inspections are not additional displayed search hits.
Retriever
All entries shown here use whole-document BM25 over ClimbMix (k1 = 0.9, b = 0.4). Piika uses the Pyserini 2.4.0 REST backend; JevGPT uses its ClimbMix adapter. No dense retriever or passage index is used by this JevGPT entry.
Budgets
JevGPT uses 1,800 seconds per question. Piika baselines retain accepted earlier outputs and documented longer continuations; see the execution settings.
Models
GPT-6.1 Sol with high reasoning effort; Gemma 4 31B IT and Qwen 3.5 9B with thinking enabled, served with vLLM.
Version
CMASS v1.0, released on 25 October 2026 as v2026.10.25. P@all, R@all and H.G. depend on the qrels, so report the version you used.

Prompts, settings and scripts: REPRODUCING.md and evaluation/.

Submit

Add your system

To submit a system, email us at sahel.sharifymoghaddam@uwaterloo.ca with the subject CMASS leaderboard submission. Include a link to your paper or project, your code, and the following:

  • System configuration: the CMASS release, model and reasoning settings, agent harness, retriever and any reranker or evidence model, time/token budgets, and pinned code and run revisions.
  • Complete run artifacts: one selected final attempt for every released question, including failed or unanswered questions; final answers; search-returned document IDs; and tool-call trajectories. Distinguish results shown to the agent from internal candidates, opened documents and final citations. For passage retrieval, include the mapping to original ClimbMix document IDs. Describe retries and how the final attempt was selected.
  • Results and publication permission: per-dataset scores and reproduction commands, with strict DSQA accuracy primary and relaxed accuracy separate. Confirm that we may publish your system name, paper/project link, and aggregate results on this leaderboard.

Use a restricted-access link for artifacts containing decoded benchmark content. We review submissions against the official evaluation protocol and frozen qrels, and compute hop groundedness using the private hop annotations. Questions about preparing a submission are welcome at the same address.
